## Session research supporting R5

`5537aad823c2e1494c196795308d93f614a9255e` deliberately restricted sessions to OAuth in [PR #2094](https://github.com/mitre/heimdall2/pull/2094). `a23b7dbef5b8add09e1d74ed66c88bc7b770b65c` added session-backed Tenable credentials in [PR #7032](https://github.com/mitre/heimdall2/pull/7032). `0c6293408` restored Passport session middleware with the OIDC fixes in [PR #6820](https://github.com/mitre/heimdall2/pull/6820).

Inspect `apps/backend/src/main.ts`, `authn/authn.controller.ts`, the local/LDAP/OIDC strategies and OAuth guard, and `tenable/tenable.controller.ts` together. Local and LDAP return the application's JWT login result; they do not need callback-state sessions. OIDC uses session-held callback state; Tenable stores remote authentication state in the session. SAML's callback uses the JWT login result, while Node-SAML owns its own request-ID cache. This supports retaining the existing OAuth-or-Tenable condition, without trying to redesign all Passport middleware in this review fix. [Node-SAML 5.1.0 source](https://github.com/node-saml/node-saml/blob/v5.1.0/src/saml.ts#L130-L137).
